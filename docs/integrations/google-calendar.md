# Google Calendar — эскиз (держим в уме)

Статус: не в активной разработке. **Не укладывается ровно в общую модель** из `README.md` — см. ниже,
это главное, что нужно решить перед тем как начинать проектировать эту интеграцию всерьёз.

## Чем отличается от остальных провайдеров

Это не таск-трекер, а календарь — сущность другого рода. Из этого два следствия:

1. **Направление синка, скорее всего, обратное** относительно остальных провайдеров: не "подтягивать
   задачи из Google Calendar", а "публиковать `Task.deadline` как событие в Google Calendar", то есть
   `Task` → событие, а не событие → `Task`. Может быть и дополнительный обратный сценарий (создание
   `Task` из события с определённым цветом/меткой), но он вторичен.
2. **Календарь личный, а не командный.** Привязка к `Project` (как у остальных провайдеров, через
   `ProjectIntegration`) здесь не подходит по смыслу — календарь принадлежит пользователю, а не проекту,
   и один пользователь может состоять в нескольких проектах, но календарь у него один. Инвариант
   "один проект — одна интеграция" (см. `README.md`) для этого провайдера, скорее всего, **не
   применим вообще** — нужна отдельная сущность `UserIntegration` (привязка к `User`, не к `Project`),
   а не переиспользование `ProjectIntegration`. Это архитектурное решение, которое нужно принять
   явно перед реализацией, а не по инерции скопировать модель остальных провайдеров.

## Auth

OAuth 2.0 через Google Cloud Console: завести проект, настроить OAuth consent screen, scope
`https://www.googleapis.com/auth/calendar.events` (только события, не весь календарь целиком).

## Push-механизм

Google Calendar Push Notifications (`watch`/`channels` API) — не классический webhook: подписка на
канал уведомлений имеет ограниченное время жизни и требует периодического переоформления
(`channels.stop` + новый `watch`), то есть нужен фоновый job на продление подписок, а не просто "один раз
настроили и забыли".

## Что синкать (черновой вариант)

- Создание/обновление/удаление события в календаре при создании/изменении/удалении `deadline` у `Task`.
- Опционально: создание `Task` из события календаря с определённым цветом/тегом (обратное направление) —
  вторичный сценарий, не обязателен для первой версии.
